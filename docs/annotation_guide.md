# Инструкция разметчика (eval v1)

Документ для разметчиков A и B (LLM-агентов) и для человека, проверяющего метки. Процедура целиком — в design doc, раздел 7.4. Схема метки — `eval/schema/label.schema.json`.

## 1. Главное правило

**Размечаем только то, что написано в снимке страницы.** Снимки лежат в `eval/gt/pages/<id>/`, список — в `eval/gt/pages/manifest.csv`. Свои знания о стипендии, другие сайты и живую страницу не используем. Если значения нет в снимке — `null` (или `unknown`), а не догадка.

**У каждого значения — дословная цитата из снимка** (поле `quote`) и имя файла снимка (поле `page`). Цитата копируется символ в символ, без кавычек вокруг, длиной от нескольких слов до 1–2 предложений. Скрипт `eval/scripts/validate.py` проверяет, что цитата есть в снимке.

Дата «сегодня» для разметки — **2026-10-25**. Целевой цикл — **начало обучения в 2027 году (2027/28)**.

## 2. Поля

### 2.1 Идентификация
- `id` — из `eval/gt/reference_list.csv`, не придумывать новый.
- `name`, `funder` — как на странице; `funder` — фонд, госорган или вуз, который платит.
- `type` — `government` / `university` / `foundation` / `erasmus_mundus` / `other`.

### 2.2 Уровень и профиль
- `levels.value` — уровни обучения, для которых стипендия: `bachelor`, `master`, `phd`, `postdoc`, `other`. Только если явно написано. «Postgraduate» в UK без уточнения — `["master", "phd"]` с цитатой.
- `fields.value` — `"any"`, если направление не ограничено, иначе краткий список направлений как на странице.
- `in_profile` — `true`, если стипендия на магистратуру и STEM/IT-направления не исключены; иначе `false`.

### 2.3 Статус цикла (`cycle_status`)
- `published` — на странице есть хотя бы один **дедлайн подачи** для цикла 2027/28;
- `only_past_cycle` — есть только даты прошлых циклов (2026/27 и раньше);
- `not_found` — дедлайнов подачи нет вообще (даже если есть другие даты).

Статус ставится строго по датам подачи, не по общему тексту вроде «applications are open». Учитываются только дедлайны с известным циклом: дедлайн с `cycle: null` (например, ежегодное «30 июня» без года и без привязки к циклу) записывается, но на статус не влияет — если других дедлайнов нет, статус `not_found`.

### 2.4 Дедлайны подачи (`application_deadlines`)
Только **последний день подачи заявки на стипендию** (или на программу, если стипендия подаётся вместе с ней — тогда это пишется в `scope_detail`).

| Поле | Как заполнять |
|---|---|
| `date` | `YYYY-MM-DD`; если известен только месяц — `YYYY-MM`; если день и месяц без года — `--MM-DD` |
| `granularity` | `day` / `month` / `day_no_year` — должно соответствовать формату `date` |
| `cycle` | `2027/28`, `2026/27`, … — по контексту страницы; если цикл из страницы не следует — `null` |
| `scope` | `global` — один для всех; `country` — зависит от страны заявителя; `university` — от вуза; `program` — от программы или курса; `applicant_group` — от группы (например, «граждане США» / «остальные») |
| `scope_detail` | для кого именно эта дата (например, `"US citizens"`, `"courses with January deadline"`); для `global` — `null` |
| `quote`, `page` | цитата и файл снимка |

Если на странице сказано «дедлайн — на странице страны / сайте вуза» без даты — **одна запись** с `date`, `granularity` по тому, что известно (например, только месяц), `scope` = `country` / `university` и пояснением в `scope_detail`. Если не известно даже месяца — дедлайн не заводим, а пишем это в `notes`.

Период «с 15 января по 1 марта» — дедлайн подачи **1 марта**; 15 января — в `other_dates` с типом `opening`.

### 2.5 Прочие даты (`other_dates`)
Тип: `opening` (открытие приёма или портала), `offer_or_documents` (дедлайн оффера от вуза, загрузки документов), `results` (объявление результатов, интервью), `other`. Формат и цитата — как у дедлайнов. **Дату оффера, результатов или открытия никогда не записываем как дедлайн подачи.**

### 2.6 Сумма (`amount`)
- Основная регулярная выплата на одного стипендиата: `value`, `currency` (ISO: EUR, GBP, USD, CAD, SEK, CHF…), `period` (`month` / `semester` / `year` / `total`) — как написано на странице, без пересчёта.
- Если ставка меняется со временем («12 000 за семестр, с осени 2027 — 13 500») — в `value` ставка для целевого цикла 2027/28, прежняя — в `variants`.
- Если указано только «покрывает всё / fully funded» без суммы — `value: null`, `full_coverage: true`.
- Если ставок несколько (Лондон / не Лондон, разные страны) — в `value` основная (первая названная), остальные текстом в `variants`.
- **Бюджет всей программы** («ежегодно выделяется 26 млн SEK») — не выплата; если других сумм нет — `value: null`, а бюджет упомянуть в `notes`.
- Суммы нет на странице — `amount: null`.

### 2.7 Что покрывает (`covers`)
`tuition`, `living`, `travel` — `true` / `false` / `null` (не сказано). Одна цитата, подтверждающая покрытие.

### 2.8 Гражданство РФ (`open_to_ru`)
- `yes` — открыта для всех национальностей / граждан стран вне ЕС, и Россия не исключена, или Россия явно в списке;
- `no` — Россия явно исключена или не входит в закрытый список стран;
- `unknown` — на странице нет условий по гражданству или список стран на другой странице.

Цитата обязательна для `yes` и `no`.

### 2.9 Ловушки (`traps`)
Отметить все подходящие: `past_cycle_only`, `country_scoped`, `university_scoped`, `program_scoped`, `month_only`, `no_year`, `multiple_date_types`, `amount_ambiguous`, `closed_to_ru`, `out_of_profile_level`, `deadline_on_other_page`, `aggregator_conflict`.

### 2.10 Служебные
- `notes` — всё, что важно для проверки и не влезло в поля (одна-две фразы).
- `annotator` — `A` или `B`; `labeled_at` — дата разметки.

## 3. Порядок работы над одной стипендией
1. Прочитать все снимки этой стипендии целиком.
2. Заполнить поля по порядку раздела 2; для каждого значения сразу скопировать цитату.
3. Перепроверить: каждая дата подачи — действительно подача? цикл указан по контексту? сумма — на одного человека?
4. Запустить `eval/scripts/validate.py` и исправить ошибки.

## 4. Спорные случаи
- Страница противоречит сама себе (две разные даты одного дедлайна) — обе даты в `application_deadlines`, пометка в `notes`, ловушка `aggregator_conflict` не ставится (это не агрегатор).
- Страница на другом языке — цитата на языке страницы.
- Непонятно, подача это или открытие, — выбрать по формулировке («closes», «deadline», «until» → подача; «opens», «from» → открытие) и записать сомнение в `notes`.

## 5. Для человека, проверяющего метки
Открыть файл снимка из поля `page`, найти цитату поиском (Ctrl+F) и проверить, что значение действительно из неё следует. Расхождения записывать в `eval/gt/adjudication.md`: id, поле, было, стало, почему.
