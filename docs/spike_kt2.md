# Спайк перед КТ2: проверка источников данных и извлечения

Дата: 25.10.2026. Скрипты: `spike/`, сырые результаты: `spike/out/` (не в git, воспроизводятся запуском скриптов).
Цель — до разметки eval-сета проверить допущения design doc: можно ли получать текст страниц своим fetch, что даёт Tavily, справляется ли LLM-извлечение с реальными страницами.

## 1. Свой fetch + trafilatura (`fetch_check.py`)

31 URL (28 официальных + 3 агрегатора), честный User-Agent бота, robots.txt соблюдается.

## 2. Tavily (`tavily_check.py`, `tavily_analyze.py`)

15 запросов из черновика eval-сета (6 discovery, 9 фактических), `max_results=10`, `search_depth=basic`, `include_raw_content=True`. Домены размечены вручную: официальные (фонд, вуз, госорган), SEO-блоги, соцсети.

| | Discovery (60 результатов) | Факт (90 результатов) |
|---|---|---|
| официальные | 18 (30 %) | 39 (43 %) |
| SEO-блоги | 23 (38 %) | 21 (23 %) |
| соцсети (facebook, instagram, reddit, youtube…) | 19 (32 %) | 27 (30 %) |
| официальный домен в топ-3 | 0 из 6 запросов | 7 из 9 запросов |

- Discovery-запросы почти не приводят на официальные страницы: выдачу забивают SEO-блоги и соцсети. Их можно использовать как **источник названий** стипендий («лиды»), после чего искать официальную страницу отдельным фактическим запросом.
- Соцсети — треть выдачи, текста у них нет. Нужен `exclude_domains`.
- Tavily Extract прочитал mastersportal (нашему fetch — 403), но не смог ox.ac.uk и scholarshipportal. Каталог Erasmus Mundus через Extract — 8k символов, но в основном навигация.
- Расход кредитов: эндпоинт `/usage` не обновился сразу после прогона; по тарифу должно быть ≈17 кредитов (15 поисков + 1 extract на 5 URL). Сверить по дашборду.

## 3. LLM-извлечение (`extract_check.py`, `grounding.py`)

Модель: `gpt-5.4-mini-2026-03-17` (замена Haiku на время тестов, ключа Anthropic нет), reasoning effort low, strict JSON-схема, у каждого значения — дословная цитата. 15 страниц с ловушками. Значения сверены вручную с текстом страниц.

| Ловушка | Страница | Результат |
|---|---|---|
| прошлый цикл на странице в октябре 2026 | Lund Global (дедлайн 16.02.2026) | ✅ `only_past_cycle` |
| страница ещё про 2026/27 | NL Scholarship | ✅ `only_past_cycle`; ⚠ не отмечено, что дедлайны задаёт каждый вуз |
| дата оффера ≠ дата подачи | Chevening timeline (8 July 2027 — оффер) | ✅ тип `offer`, подача — «October 2026», по странам |
| дедлайн без года | Commonwealth Master's («Tuesday 20 October») | ✅ год не выдуман; ❌ формат даты не по схеме — нужна валидация кодом |
| начало и конец периода подачи | Heinrich Böll (15.01–01.03.2027) | ❌ дата открытия портала записана как дедлайн |
| сумма программы ≠ сумма на человека | Lund (SEK 26 млн в год на всю программу) | ❌ записано как сумма стипендии |
| дедлайн не на странице | DAAD detail, Rhodes | ❌ статус `confirmed` без дат подачи |
| PhD вместо магистратуры | Vanier | ✅ уровень `phd` |
| SEO-страница | opportunitiescorners (Gates), opportunitiesnexus (DAAD) | ✅ значения совпадают с официальными |

- **Опасных ошибок** (дедлайн позже реального или прошлый цикл выдан за текущий): **0 из 15**.
- Ошибок в отдельных полях: 5 (Böll — тип даты, Lund — сумма, Rhodes и DAAD — статус, Commonwealth — формат), плюс 2 мелкие (уровень у Gates `other`, нет области дедлайна у NL).
- Цитаты: 53 / 53 найдены в тексте (после нормализации кавычек и markdown).
- Токены: 39k входа / 9,4k выхода на 15 страниц ≈ 2,6k / 0,6k на страницу; задержка 1,3–5 с.

## 4. Что меняем в design doc

1. **Модель данных дедлайна:** дата + точность (день / месяц) + тип (подача / оффер / результаты / открытие) + область (общий / страна / вуз / программа / группа заявителей). Одна стипендия может иметь много дедлайнов (Chevening, DAAD — по странам; NL, Gates — по вузу или курсу).
2. **Статус цикла считается кодом по извлечённым датам, а не моделью** (ошибки Rhodes и DAAD). Валидатор проверяет формат дат и наличие цитаты.
3. **Discovery в два шага:** широкий поиск → лиды (названия) → поиск официальной страницы с `include_domains` / по домену фонда → обход подстраниц `timeline|dates|deadline|apply` на 1 уровень. Плюс seed-каталоги: детальные страницы DAAD, списки вузов.
4. **Стоимость U1:** меньше токенов на страницу, чем закладывали (2,6k против 10k), но страниц на кандидата больше (основная + 1–3 подстраницы). Пересчитать после выбора модели.
5. **Риски (раздел 10):** блокировка ботов агрегаторами, JS-каталоги, протухание ссылок, дедлайны «по странам» на отдельных страницах, ToS агрегаторов при чтении через Tavily.
6. **Eval:** найденные ловушки — готовые примеры для eval-сета (тип даты, прошлый цикл, сумма программы, дедлайн без года, дедлайн по стране).
